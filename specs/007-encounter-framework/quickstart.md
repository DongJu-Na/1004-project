# Quickstart: 인카운터 프레임워크 검증

## 1. 자동 테스트
EditMode `Encounter.Tests.EditMode` 6묶음 + 001~006 회귀.

## 2. 씬
`Tools > PROJECT 1028 > Build Encounter Test Scene`. 도로(긴 띠), Truck, 트리거 6개(도로 위 원), P1·P2, 시스템·패널. 좌하단 인카운터 패널: 후보 수·발생 수·다음 가능 시점·플래그·이력·확정 대기·샘플 단가 합계.

## 3. 시나리오
| US | 조작 | 기대 |
|---|---|---|
| 1 | 도로를 걸어 트리거 진입(여러 번) | 확률 통과 시 NPC 등장·대사 3~5줄·종료 후 플래그 기록. 패널 로그 "발생/스킵(사유)" |
| 2 | `X`로 샘플 8개 순서대로 강제 | A: 플래그만·의심 불변 / B: 시야 안이면 002 사건 / C: "1/2" 선택 전 진행 불가, 선택별 플래그 / D: 플래그 0·의심 0·이력만 |
| 3 | 차량 탑승 후 트리거 통과 vs 도보 | 패널 통계에서 차량 확률↑. 런 4개 도달 후 스킵(상한). 직후 재진입 스킵(간격). `S` 정찰 중 → 스킵. 밤 전용 샘플은 낮에 후보 제외(N 전환) |
| 4 | C 샘플 "안 태운다" 선택 후 `X` 반복 | 회수 변주(`sample_c_runaway_ledger`)가 후보에 포함되어 발생. 패널 회수 조회 결과 표시 |
| Z | 100런 시뮬 | 발생 수 전부 2~4, 간격 위반 0, 원본 중복 0, 조건 위반 0 |
