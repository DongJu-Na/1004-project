# Feature Specification: 플레이 기반 (Play Foundation)

**Feature Branch**: `001-play-foundation`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "기반 기능. 플레이 기반: 3인칭 이동·카메라·상호작용, NPC 뼈대, 최소 대화 표시. 근거는 Docs/PrototypePlan.md 1단계(플레이어 이동, 카메라, 상호작용 기반)와 3단계(NPC 대화와 단순 상태). 게임 규칙 요소(의심 수치, 진영 판정, 위협 반응)는 포함하지 않는다. 기존 Assets/Scripts/Player/ThirdPersonMotor.cs를 출발점으로 한다. NPC는 위치·시야 방향·"플레이어를 보고 있는가" 상태·대화 트리거만 가지며, 대화는 데이터 파일에서 읽은 3~5줄 텍스트를 순서대로 표시한다. 완료 기준은 PrototypePlan의 "키보드/마우스로 도보 이동과 카메라 회전이 자연스럽다"와 "NPC와 대화해 목적지를 받는다". 신규 에셋 없음(기존 모델·애니메이션 사용). 싱글과 코옵 동작 차이 없음(플레이어 개체가 1명 이상일 뿐). 테스트 씬 하나에서 단독 검증 가능해야 한다."

## Constitution Compliance *(constitution v1.1.0)*

- **기능 분류 (원칙 I)**: **기반 기능**. 이 스펙은 새로운 게임 규칙을 도입하지 않는다.
  의심 수치(SDD §2), 진영 판정(§3.2), 위협 반응(§3~§5), 시간대 배율(§7)은 포함하지 않는다.
  NPC의 "플레이어를 보고 있는가" 상태는 순수 감지 결과일 뿐이며, 그 결과로 NPC의 행동이나
  어떤 수치도 바뀌지 않는다. 이 상태를 소비하는 규칙은 후속 게임 규칙 기능(의심 시스템)이 정한다.
- **근거 문서 (원칙 I)**: `Docs/PrototypePlan.md` 1단계 "플레이어 이동, 카메라, 상호작용 기반",
  3단계 "NPC 대화와 단순 상태", 완료 기준 항목 1 "키보드/마우스로 도보 이동과 카메라 회전이
  자연스럽다" 및 항목 3 "NPC와 대화해 목적지를 받는다". 각 요구사항은 아래에서 `[PP-1]`, `[PP-3]`,
  `[PP-완료1]`, `[PP-완료3]`으로 인용한다.
- **범위 밖 준수 (근거 문서 §)**: PrototypePlan이 범위 밖으로 둔 전투, 다수 NPC 스케줄, 래그돌,
  온라인, 실제 섬 규모 맵, 복수 차량, 최종 아트·사운드는 포함하지 않는다. 차량(2단계), 미션 목표
  HUD(4단계), 컷신·저장(5단계)도 이 기능의 범위 밖이다.
- **신규 에셋 (원칙 II)**: 없음. 저장소의 Models·Animations·Prefabs·Data 폴더가 현재 비어 있으므로
  플레이어와 NPC는 엔진 기본 프리미티브(캡슐·큐브)로 표현한다. 예산 초과 항목 없음.
- **독립 검증 (원칙 III)**: 테스트 씬 하나에서 맵·의심·제압·인카운터 없이 검증한다.
- **싱글·코옵 동작 (원칙 IV)**: 동작 차이 없음. 플레이어 개체가 1개 이상 존재할 뿐이며, 이동·카메라·
  상호작용·시야 판정은 모두 플레이어 개체 단위로 독립 동작한다. 네트워크 동기화는 PrototypePlan
  범위 밖(온라인)이므로 포함하지 않는다. 코옵 동작은 같은 씬에 플레이어 개체 2개를 배치해 검증한다.
- **폐기 항목 (원칙 V)**: 무기·공격 입력을 두지 않는다. 상호작용 입력은 "대화·조사" 용도만 가진다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 도보 이동과 카메라 (Priority: P1)

플레이어는 키보드로 걷고 달리며, 마우스로 카메라를 돌려 3인칭 시점에서 캐릭터 주변을 본다.
이동 방향은 카메라가 보는 방향 기준이다. `[PP-1]` `[PP-완료1]`

**Why this priority**: 나머지 모든 기능(상호작용·대화·후속 의심 시스템)이 "플레이어가 NPC 앞까지
간다"를 전제한다. 이것만 있어도 테스트 씬을 돌아다니며 손맛을 평가할 수 있다.

**Independent Test**: 바닥과 장애물 몇 개만 있는 테스트 씬에서 이동·달리기·카메라 회전을 60초간
수행하고, 아래 수용 시나리오를 모두 만족하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 평지에 서 있다, **When** 이동 키를 누른다, **Then** 캐릭터가 카메라가 보는
   방향을 기준으로 해당 방향으로 걷기 시작하고, 캐릭터의 정면이 이동 방향으로 부드럽게 돌아간다.
2. **Given** 플레이어가 걷고 있다, **When** 달리기 키를 함께 누른다, **Then** 이동 속도가 눈에 띄게
   빨라지고, 키를 떼면 걷기 속도로 돌아온다.
3. **Given** 플레이어가 정지해 있다, **When** 마우스를 좌우·상하로 움직인다, **Then** 카메라가
   캐릭터를 중심으로 궤도 회전하며, 상하 각도는 바닥 아래나 머리 위를 넘어가지 않는 범위로 제한된다.
4. **Given** 카메라와 캐릭터 사이에 벽이 있다, **When** 플레이어가 벽에 등을 대고 선다, **Then**
   카메라가 벽을 뚫고 밖을 보지 않고 캐릭터 쪽으로 당겨진다.
5. **Given** 플레이어가 이동 키를 떼었다, **When** 0.5초가 지난다, **Then** 캐릭터가 미끄러지지 않고
   멈춰 있다.

### User Story 2 - NPC에게 말을 걸어 목적지를 받는다 (Priority: P2)

플레이어가 NPC 가까이 가면 "말하기" 안내가 뜬다. 상호작용 키를 누르면 데이터 파일에 적힌 3~5줄의
대사가 한 줄씩 순서대로 표시되고, 마지막 줄이 끝나면 목적지 하나가 플레이어에게 전달되어 씬 안에
표시된다. `[PP-3]` `[PP-완료3]`

**Why this priority**: PrototypePlan 완료 기준 항목 3을 직접 충족한다. 후속 인카운터 시스템
(SDD §6.1 "대사 3~5줄")이 그대로 재사용할 대화 표시 방식을 여기서 확정한다.

**Independent Test**: 테스트 씬에 NPC 1개와 대사 4줄이 담긴 데이터 파일을 두고, 접근 → 안내 표시 →
상호작용 → 4줄 순차 표시 → 목적지 표시까지 한 번에 재현한다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 NPC로부터 상호작용 거리 밖에 있다, **When** 상호작용 거리 안으로 들어간다,
   **Then** 화면에 "말하기" 안내가 나타나고, 거리 밖으로 나가면 사라진다.
2. **Given** "말하기" 안내가 표시되어 있다, **When** 상호작용 키를 누른다, **Then** 대사 첫 줄이
   표시되고 플레이어 이동과 카메라 회전이 멈춘다.
3. **Given** 대사 한 줄이 표시되어 있다, **When** 진행 키를 누른다, **Then** 다음 줄이 표시된다.
   데이터 파일의 줄 순서와 화면 표시 순서가 같다.
4. **Given** 마지막 줄이 표시되어 있다, **When** 진행 키를 누른다, **Then** 대화창이 닫히고 이동이
   다시 가능해지며, 씬 안의 목적지 위치에 마커가 나타난다.
5. **Given** 대화가 끝났다, **When** 같은 NPC에게 다시 말을 건다, **Then** 대사가 처음부터 다시
   표시되고 목적지 마커는 중복 생성되지 않는다.

### User Story 3 - NPC 뼈대: 위치·시야 방향·"보고 있는가" (Priority: P3)

NPC는 씬 안에 서서 정면 방향을 가진다. 플레이어가 NPC의 시야 부채꼴 안, 시야 거리 안에 있고 그
사이에 가리는 물체가 없으면 NPC는 "플레이어를 보고 있는" 상태가 된다. 이 상태는 테스트 씬에서
확인 가능하게 표시되지만, NPC의 행동을 바꾸지는 않는다. `[PP-3]`

**Why this priority**: 후속 의심 시스템(SDD §2)이 소비할 유일한 감지 입력이다. 여기서 감지 정확도를
확정해두어야 의심 상승 원인을 감지 오류와 규칙 오류로 나눠 추적할 수 있다(헌장 원칙 III).

**Independent Test**: NPC 1개를 두고 플레이어를 NPC 정면·측면·후면·장애물 뒤로 이동시키며 "보고
있는가" 표시가 기대와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 NPC 정면, 시야 거리 안에 있다, **When** 두 사람 사이에 가리는 물체가 없다,
   **Then** NPC는 "보고 있음" 상태다.
2. **Given** 플레이어가 NPC 정면에 있다, **When** 두 사람 사이에 벽이 있다, **Then** NPC는 "보고
   있지 않음" 상태다.
3. **Given** 플레이어가 NPC 바로 뒤에 있다, **When** 시야 거리 안이더라도, **Then** NPC는 "보고 있지
   않음" 상태다.
4. **Given** 플레이어가 NPC 정면에 있다, **When** 시야 거리 밖으로 물러난다, **Then** 상태가 "보고
   있지 않음"으로 바뀐다.
5. **Given** NPC가 "보고 있음" 상태다, **When** 5초가 지난다, **Then** NPC의 위치·방향·대사·표시
   가운데 어떤 것도 바뀌지 않는다(행동 반응 없음).

---

### User Story 4 - 코옵 동등성: 플레이어 개체 2개 (Priority: P4)

같은 씬에 플레이어 개체가 2개 있을 때, 각 개체는 자기 입력·자기 카메라로 독립 동작하고, NPC의
"보고 있는가"와 "말하기" 안내는 플레이어 개체별로 따로 판정된다. `[PP-1]` `[PP-3]` (헌장 원칙 IV)

**Why this priority**: 헌장 원칙 IV는 모든 규칙이 싱글·코옵에서 동일해야 한다고 요구한다. 기반
단계에서 플레이어 단위 독립성을 확보해두지 않으면 후속 의심 시스템의 "개인 의심은 플레이어별"
(SDD §8.1)을 구현할 수 없다.

**Independent Test**: 테스트 씬에 플레이어 개체 2개를 배치하고(입력은 하나만 활성), 한 개체를 NPC
정면에, 다른 개체를 뒤에 두어 "보고 있는가"가 개체별로 다르게 판정되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어 개체 A는 NPC 정면, B는 NPC 후면에 있다, **When** 상태를 조회한다, **Then**
   NPC는 A에 대해 "보고 있음", B에 대해 "보고 있지 않음"이다.
2. **Given** A가 NPC와 대화 중이다, **When** B가 이동 입력을 받는다, **Then** B는 정상적으로
   이동한다(A의 대화가 B의 이동을 막지 않는다).
3. **Given** 씬에 플레이어 개체가 1개만 있다, **When** 동일한 시나리오를 수행한다, **Then** 결과가
   개체 2개일 때의 각 개체 결과와 같다.

---

### Edge Cases

- 대화 데이터 파일이 없거나 비어 있으면: 대화가 시작되지 않고 테스트 씬에 오류 표시가 남는다.
  게임은 멈추지 않는다.
- 대화 데이터가 2줄 이하이거나 6줄 이상이면: 있는 줄을 그대로 표시하되 테스트 씬에 "3~5줄 규격
  위반" 경고를 남긴다.
- 대화 중 플레이어가 상호작용 거리 밖으로 밀려나면(외부 힘 등): 대화는 끝까지 유지된다.
  대화 중에는 이동이 잠겨 있으므로 정상 플레이에서는 발생하지 않는다.
- 상호작용 거리 안에 NPC가 2개 이상이면: 카메라가 보는 방향에 가장 가까운 NPC 하나만 안내
  대상이 된다.
- 플레이어가 바닥 밖으로 떨어지면: 씬 시작 위치로 되돌아온다.
- 시야 판정 경계(부채꼴 가장자리, 시야 거리 끝)에서 상태가 매 프레임 깜빡이면: 상태 전환에 짧은
  안정 시간을 두어 깜빡임을 막는다.
- 상호작용 키와 진행 키가 같은 키일 때: 대화 시작 입력이 첫 줄을 건너뛰지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**이동·카메라** `[PP-1]` `[PP-완료1]`

- **FR-001**: 플레이어는 키보드 방향 입력으로 캐릭터를 카메라 기준 8방향 이상(아날로그 포함)으로
  이동시킬 수 있어야 한다.
- **FR-002**: 플레이어는 별도 입력으로 걷기와 달리기를 전환할 수 있어야 하며, 두 속도는 시각적으로
  구분되어야 한다.
- **FR-003**: 캐릭터의 정면은 이동 방향으로 부드럽게 회전해야 한다(즉시 스냅 금지).
- **FR-004**: 플레이어는 마우스로 카메라를 캐릭터 중심으로 좌우 무제한, 상하 제한 범위 안에서 궤도
  회전시킬 수 있어야 한다.
- **FR-005**: 카메라는 캐릭터와 카메라 사이의 장애물을 뚫고 보지 않도록 캐릭터 쪽으로 당겨져야 한다.
- **FR-006**: 이동 입력이 없으면 캐릭터는 짧은 감속 뒤 완전히 정지해야 한다.
- **FR-007**: 기존 이동 구현(`Assets/Scripts/Player/ThirdPersonMotor.cs`)의 이동·달리기·회전
  동작을 출발점으로 삼고, 이 스펙의 요구사항에 맞지 않는 부분만 조정한다.

**상호작용·대화** `[PP-3]` `[PP-완료3]`

- **FR-008**: 플레이어가 상호작용 가능한 NPC의 상호작용 거리 안에 들어오면 화면에 "말하기" 안내가
  표시되고, 벗어나면 사라져야 한다.
- **FR-009**: 안내가 표시된 상태에서 상호작용 입력을 하면 그 NPC의 대화가 시작되어야 한다.
- **FR-010**: 대화 내용은 씬 밖의 데이터 파일에서 읽어야 하며, 파일은 NPC별로 3~5줄의 대사와
  목적지 1개를 담는다.
- **FR-011**: 대사는 한 번에 한 줄씩, 데이터 파일의 순서대로, 플레이어의 진행 입력마다 다음 줄로
  넘어가며 표시되어야 한다.
- **FR-012**: 대화 중에는 해당 플레이어의 이동과 카메라 회전이 잠겨야 하고, 대화가 끝나면 즉시
  풀려야 한다.
- **FR-013**: 마지막 대사가 끝나면 데이터 파일의 목적지가 플레이어에게 전달되어 씬 안 해당 위치에
  마커로 표시되어야 한다. 같은 NPC와 다시 대화해도 마커는 하나만 유지된다.
- **FR-014**: 대화 데이터가 없거나 규격(3~5줄)을 벗어나면 게임을 멈추지 않고 테스트 씬에 확인
  가능한 경고를 남겨야 한다.

**NPC 뼈대** `[PP-3]`

- **FR-015**: NPC는 씬 안의 위치와 정면 방향을 가져야 한다.
- **FR-016**: NPC는 각 플레이어 개체에 대해 "보고 있는가" 상태를 가져야 한다. 상태는 플레이어가
  (a) NPC 정면 기준 시야 부채꼴 안, (b) 시야 거리 안, (c) 가리는 물체 없음을 모두 만족할 때만 참이다.
- **FR-017**: "보고 있는가" 상태 변화는 경계에서 깜빡이지 않도록 짧은 안정 시간을 거쳐 반영되어야 한다.
- **FR-018**: "보고 있는가" 상태는 NPC의 위치·방향·대사·표시를 포함한 어떤 행동도 바꾸지 않아야
  한다. 상태는 후속 기능이 읽을 수 있도록 외부에 노출만 된다.
- **FR-019**: 테스트 씬에서 NPC의 시야 부채꼴·시야 거리·현재 "보고 있는가" 상태를 눈으로 확인할 수
  있어야 한다.

**독립 검증·코옵 동등성** (헌장 원칙 III, IV)

- **FR-020**: 위 모든 요구사항은 바닥·장애물 몇 개·NPC 1~2개·플레이어 개체 1~2개만 있는 테스트 씬
  하나에서 검증 가능해야 한다. 맵, 의심, 제압, 인카운터, 차량, 저장은 필요하지 않다.
- **FR-021**: 이동·카메라·상호작용 안내·대화 잠금·"보고 있는가"는 모두 플레이어 개체 단위로 독립
  동작해야 한다. 한 개체의 대화가 다른 개체의 이동을 막지 않아야 한다.
- **FR-022**: 플레이어 개체가 1개일 때와 2개일 때 각 개체가 경험하는 동작은 같아야 한다.

### Key Entities

- **플레이어 개체**: 씬 안에서 조작되는 캐릭터 하나. 위치, 정면 방향, 이동 상태(정지·걷기·달리기),
  대화 잠금 여부, 자기 카메라, 수령한 목적지를 가진다. 씬에 1개 이상 존재할 수 있다.
- **NPC**: 씬 안에 서 있는 인물. 위치, 정면 방향, 시야 부채꼴 각도, 시야 거리, 상호작용 거리, 연결된
  대화 데이터, 플레이어 개체별 "보고 있는가" 상태를 가진다. 이 스펙에서는 이동하지 않는다.
- **대화 데이터**: NPC 하나에 연결된 씬 밖 데이터. 대사 줄 목록(3~5줄, 순서 있음)과 목적지 1개를
  담는다.
- **목적지**: 씬 안의 위치 하나와 표시 이름. 대화 종료 시 플레이어 개체에 전달되고 마커로 표시된다.
- **상호작용 안내**: 플레이어 개체 화면에 뜨는 "말하기" 표시. 대상 NPC 하나를 가리킨다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이동 입력 후 캐릭터가 움직이기 시작하기까지, 그리고 마우스 입력 후 카메라가 돌기
  시작하기까지 사용자가 지연을 느끼지 않는다(입력 후 다음 화면 갱신 안에 반응).
- **SC-002**: 프로토타입 담당자 3명이 테스트 씬에서 60초씩 이동·카메라를 시험한 뒤 "자연스럽다"에
  전원 동의한다(PrototypePlan 완료 기준 1). 동의하지 않은 항목은 구체적 현상으로 기록된다.
- **SC-003**: 테스트 씬을 열고 2분 안에 "NPC 접근 → 대화 3~5줄 → 목적지 마커 표시"를 처음 시도하는
  사람이 안내 없이 완료할 수 있다(PrototypePlan 완료 기준 3).
- **SC-004**: 데이터 파일의 대사 줄 순서와 화면 표시 순서가 100% 일치한다. 파일 내용을 바꾸면 재시작
  후 바뀐 내용이 표시된다.
- **SC-005**: "보고 있는가" 판정은 정면·후면·장애물 뒤·거리 밖 네 가지 배치 각 10회 시험에서 40회
  모두 기대값과 일치하고, 경계 위치에 정지해 있을 때 1초 안에 상태가 2회 이상 바뀌지 않는다.
- **SC-006**: 플레이어 개체 2개 배치 시 NPC의 "보고 있는가"가 개체별로 다르게 판정되는 사례를 1회
  이상 재현하고, 한 개체의 대화 중 다른 개체의 이동이 정상 동작한다.
- **SC-007**: 이 기능을 위해 저장소에 추가되는 신규 아트·애니메이션·사운드 에셋은 0개다.

## Assumptions

- **에셋**: Models·Animations·Prefabs·Data 폴더가 비어 있으므로 플레이어와 NPC는 엔진 기본
  프리미티브로 표현한다. 걷기·달리기 애니메이션은 없고 속도 차이로만 구분한다. 후속 에셋 도입은
  별도 스펙에서 원칙 II에 따라 다룬다.
- **점프**: 기존 이동 구현에 점프가 있다. SDD v0.8에 점프 관련 조항이 없으므로 이 스펙은 점프를
  요구하지도 제거하지도 않는다. 유지 여부는 후속 게임 규칙 기능에서 정한다.
- **카메라 상하 제한**: 바닥 아래·머리 위를 넘지 않는 일반적인 3인칭 범위를 기본값으로 한다.
- **상호작용 거리·시야 각도·시야 거리**: 테스트 씬에서 조정 가능한 값으로 두며 초깃값은 구현 단계에서
  정한다. 이 값들은 게임 규칙이 아니라 감지 파라미터이며, 의심 시스템 스펙에서 SDD 근거로 재확정한다.
- **대화 진행 입력**: 상호작용 키와 같은 키를 기본값으로 한다. 대화 시작 입력이 첫 줄을 건너뛰지
  않도록 처리한다.
- **목적지 표시**: 씬 안 마커만 표시한다. 화면 HUD·거리 표시·미션 완료 판정은 PrototypePlan 4단계
  범위이므로 이 스펙에 포함하지 않는다.
- **입력 장치**: 키보드와 마우스만 대상으로 한다. 게임패드는 범위 밖이다.
- **코옵 검증 방식**: 로컬 씬에 플레이어 개체 2개를 두고 한 개체만 입력을 받는 방식으로 개체 단위
  독립성을 검증한다. 두 번째 개체의 실시간 조작과 네트워크 동기화는 범위 밖이다.
- **선행 SDD 인용**: 이 스펙은 SDD v0.4~v0.7을 인용하지 않는다. 근거는 `Docs/PrototypePlan.md`만이다.
- **의존성**: 저장소에 이미 있는 Input System 패키지와 기존 이동 구현을 재사용한다. 그 외 새 외부
  의존성은 없다.
